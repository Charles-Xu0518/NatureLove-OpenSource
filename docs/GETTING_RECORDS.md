# 从微信取得一份可分析的记录

第一次操作先按 [README 的 Mac 六步流程](../README.md#获取聊天记录)走。这里补充数据目录、密钥获取失败、官方微信恢复和归档核对。界面按 WeChatDataAnalysis v2.10.0 核对，日期为 2026-10-23；后续版本以其说明为准。

保留两份东西：一份完整的原始导出，里面有消息和附件；一份供 Nature Love 使用的标准 JSON。转换文件不能代替原始归档。

## 本项目实际采用的路线

前期用微信流（WeChatBridge）接收过少量合并转发，取得的是片段。完整归档则在 iPhone 记录迁移到 Mac 后，先获取并校验本地数据库密钥，再由 WeChatDataAnalysis 本地服务导出 JSON 和媒体，最后另行整理通话会话与附件清单。

以下主程序流程是给其他使用者的操作说明。临时微信的具体实现由导出工具负责，没有打包进 Nature Love；本项目的转换脚本不读取数据库，也不获取密钥。

## 安装与 Mac 权限

| 项目 | 做法 |
|---|---|
| 系统与芯片 | “关于本机”检查 macOS 和芯片。上游桌面包要求 macOS 15+、Apple Silicon；Intel 不按本教程视为已验证 |
| 导出工具 | 从[上游 Releases](https://github.com/LifeArchiveProject/WeChatDataAnalysis/releases/latest)下载 Mac ARM64 包，放进“应用程序”后启动 |
| 微信 | 使用官方微信，实验性捕获要求 `/Applications/WeChat.app`；不是聊天数据目录 |
| 完全磁盘访问权限 | 系统设置 → 隐私与安全性 → 完全磁盘访问权限；添加实际运行的 WeChatDataAnalysis，退出后重开 |
| 辅助功能 | 仅在图片扫描确实提示需要时，给执行扫描的应用或终端授权；这项权限与完全磁盘访问不同 |
| LLDB | 仅实验性调试路线需要；提示缺少时执行 `xcode-select --install`，按系统窗口完成安装 |
| 空间与备份 | 预留官方微信恢复副本、解密数据库和媒体归档的空间，操作前保留重要数据备份 |

源码运行时，应使用上游[完整桌面开发方式](https://github.com/LifeArchiveProject/WeChatDataAnalysis/blob/v2.10.0/README.md#2-从源码运行开发者高级用户)。只启动网页或后端，不一定具有桌面原生组件和权限。不要给一个未参与运行的浏览器授权后，以为服务已取得磁盘访问权限。

首次打开应用的来源限制见 [Apple 说明](https://support.apple.com/zh-cn/102445)。如果提示软件损坏、恶意软件或签名失效，先核对下载来源和安装包，不将关闭系统保护作为修复步骤。

## 找到当前账号的数据目录

工具中的两个路径分别是：

- **微信安装路径**：通常是 `/Applications/WeChat.app`。
- **数据库存储路径**：当前账号的 `db_storage`，里面有消息库、会话库等；不是 `.app`。

先用工具自动发现账号。多账号时对照头像、昵称和当前微信登录身份，不把名称相近的旧目录当作同一个账号。

手动定位微信 4.x 活动数据时，在访达按 `⌘⇧G`，粘贴：

```text
~/Library/Containers/com.tencent.xinWeChat/Data/Documents/app_data/xwechat_files/
```

进入实际账号目录，通常能看到：

```text
<账号目录>/
├── db_storage/
│   ├── message/
│   ├── session/
│   └── ...
└── ...
```

选中 `db_storage`，按 `⌥⌘C` 复制完整路径，填入“数据库存储路径”。`~` 表示当前用户主目录；访达会展开它，不需要在公开教程里写自己的用户名。

同一台 Mac 可能同时存在旧的 `Documents/xwechat_files` 与新的 `Documents/app_data/xwechat_files`。对微信 4.x 应优先核对后者的活动库。路径不在这里时，以工具发现及微信实际使用的位置为准，不能仅凭目录存在就认定它是当前数据。

## 默认密钥获取与验真

1. 在主程序选择账号，进入“数据库解密”，确认 `db_storage` 指向该账号。
2. 点击“一键获取数据库密钥”，等页面开始等待。默认受控组件要求在此时完整退出微信程序，再打开并登录同一账号；不要提前重启后才点击获取。
3. 完成手机确认，保持主程序运行。
4. 获取成功后查看“解密密钥”框。应是 64 个十六进制字符；从其他受信任的本地工具取得密钥时，复制值本身，不要连 JSON 字段名、引号或前缀一起粘贴。
5. 点击“开始解密”，核对成功、失败和错误详情。进入目标聊天后抽查正文与日期，再认为这份数据可以使用。

**成功要看数据库校验和实际读取结果，不能只看“找到了候选”或字符数量。** 同一设备的另一个账号、旧数据副本或单个数据库派生值，不一定能解开当前账号的全部库。

不要把数据库密钥填进 Nature Love 配置。导出完成后，分析只需要 JSON 和本地附件。

## 实验性兜底的登录顺序

只有主程序明确提供这条路线时才使用。它会创建恢复备份、临时重签微信并请求管理员授权；成功、停止或失败后应恢复原版。具体兼容范围见[上游捕获说明](https://github.com/LifeArchiveProject/WeChatDataAnalysis/blob/v2.10.0/docs/MACOS_KEY_CAPTURE.md)。

| 阶段 | 你要做的操作 | 可以继续的标志 |
|---|---|---|
| 准备 | 阅读风险提示并选择继续，完成系统授权 | 工具已准备临时微信 |
| 第一次登录 | 在临时微信登录同一账号，完整进入聊天页 | 点击“已进入聊天，开始预检”后，预检通过 |
| 退出账号 | 在微信中选择“退出登录”，停在二维码页 | 此时先不扫码，不退出导出工具 |
| 启动监测 | 点“已看到二维码，开始监测”，完成管理员授权 | 页面明确显示“监测已就绪” |
| 第二次登录 | 就绪后再登录同一账号，完成手机确认 | 工具进入捕获、校验和恢复阶段 |
| 完成 | 等待最终结果，不因临时窗口关闭就再次登录 | 密钥回填、校验通过，且官方微信恢复完成 |

第一次登录用于检查当前版本是否可捕获；第二次登录才是在监测已就绪后读取本次登录产生的候选。顺序颠倒可能错过时机。预检没有通过，就不继续退出账号或反复扫码。

中途取消用“停止并恢复”。若程序意外退出，重新打开解密页，先处理检测到的遗留恢复事务，再发起新一轮。恢复阶段不要更新或替换微信安装文件。

## 独立 WeData 密钥提取器

上游另有 [WeDataKeyExtractor 源码与说明](https://github.com/LifeArchiveProject/WeChatDataAnalysis/blob/v2.10.0/macos-key-extractor/README.md)，与主程序是两个入口。v2.10.0 的常规 Release 资产未单列独立提取器安装包，不要把主程序 ZIP 当成它；需要独立入口时按上游构建说明取得应用。

使用独立应用时：放进“应用程序”并授予完全磁盘访问权限，选择本机活动账号，点“检查环境并开始”。准备后点“显示微信窗口”，手动打开，再点“我已手动打开，检查启动”；后续仍按第一次登录、预检、退出账号、等待监测就绪、第二次登录的顺序。

成功并恢复原版后，用工具的“复制密钥”功能，将值填入主程序“数据库解密”页。该独立工具的缓存是 `~/.wcdb-key-tool/wechat-passphrase.json`；这不是主程序的通用缓存路径，没有此文件不代表主程序获取失败。缓存含私密密钥，不能作为聊天 JSON 输入，也不要附进问题反馈。

## 获取失败和恢复

| 现象 | 先检查什么 |
|---|---|
| 找不到账号或没有访问权限 | 完全磁盘访问是否给到实际应用；授权后是否重开；是否选中了当前 `db_storage` |
| 本地组件不可用、完整性或签名校验失败 | 更新或重装上游完整桌面包；源码运行检查原生组件。该类失败不应靠跳过组件校验解决 |
| 提示缺少 LLDB | 安装 Xcode Command Line Tools 后重试；不是再装一个 Python 包 |
| 获取超时 | 是否在开始获取后才重启微信；实验性路线是否等到“监测已就绪”才第二次登录 |
| 临时微信登录后退出、预检不支持 | 用“停止并恢复”结束，记录系统、芯片、微信版本和失败阶段；不能把窗口关闭当成功 |
| 密钥已有但解密失败 | 对照账号、活动数据目录和失败库；不要将某个库的成功当作全部成功 |
| 看到文字却打不开图片 | 完成图片密钥校验，确认原图片仍在 Mac；数据库密钥和图片密钥不能互换 |
| 提示恢复未完成 | 先使用“立即恢复官方版本”或“停止并恢复”，保留恢复资产；此时不开始新捕获 |

需要手动查看恢复后的应用签名时，可以在终端运行只读检查：

```bash
codesign --verify --deep --strict --verbose=2 /Applications/WeChat.app
codesign -dv --verbose=4 /Applications/WeChat.app 2>&1
```

第一条应通过，第二条应显示 `Identifier=com.tencent.xinWeChat` 和腾讯 `TeamIdentifier=5A4RE8SF68`。这只是辅助检查，仍以工具对本次原版、版本及恢复事务的完整校验为准；单看签名通过不能证明恢复的是原来那一版。

## 图片、表情与语音

数据库解密后，“图片密钥”页可能自动回填 XOR / AES。需要时点击“扫描微信内存”，按页面提示操作，并用实际照片检查结果。只需要读取消息时可以跳过批量图片预解密；要保留照片时，至少先确认聊天页能打开图片原件。

表情在“批量下载表情包”页处理，点“开始下载表情”。它会联网查找可取得的文件，过期或无法访问的资源仍可能缺失。先完成下载，再创建新的 JSON 媒体导出；不要认为旧 ZIP 会自动增加补回的文件。

语音附件与语音转写分别保存。首次归档可以跳过本地模型转写，仍然保留音频文件；通话通知没有当时通话的声音或画面。

## 导出 JSON 和全部可用附件

在聊天页选目标联系人，点“导出聊天记录”，先确认只选中这一段单聊。想做正文和媒体分析时关闭该工具的隐私模式，否则正文会隐藏、媒体也不导出。这个设置只影响保存在自己电脑里的原始包，不表示要公开它。

隐私模式开关在侧边栏的眼睛图标。悬停提示“关闭隐私模式”时，点击关闭；再打开导出面板，确认顶部不再提示隐藏正文和媒体。

| 设置 | 内容 |
|---|---|
| 文件格式 | JSON（默认通常为 HTML，需要切换） |
| 消息类型 | 保持全部选中；已经显示“取消全选”时，不要再点该按钮 |
| 时间范围 | 开始与结束都留空为全部时间 |
| 语音转文字 | 可不选；选中时需先配置可用的本地语音模型 |
| 输出方式 | 首次选 ZIP 全量；持续更新选增量目录 |
| 保存位置 | “选择目录”，使用私人目录；不要把它设成源码目录 |

图片、视频、表情、语音和文件选中后，会带入可用的本地资源。这一版没有额外的附件总开关。导出数量到达总数后，继续等任务状态结束和文件保存完成；ZIP 还可能有打包与写入阶段。

ZIP 导出后保留压缩包，并解压出完整目录。增量目录可直接浏览，首次运行会写入当前范围，后续运行按基线更新；不要删除 `.wechat-chat-export.json`，也不要把不同账号的基线混用。“下载远程缩略图”属于 HTML 的可选联网功能，不是补齐所有 JSON 媒体的按钮。

供分析使用的是 `conversations/<目标会话>/messages.json`。根目录 `manifest.json` 描述导出任务，`report.json` 记录检查与缺失；`meta.json` 只有会话元数据，都不能替代消息正文。

另导出 HTML 时换一个保存目录，用于查看文字和附件是否对应。两种导出保留各自的原始结构，不手工拼成一个覆盖目录。

记下 macOS、微信与导出工具版本、导出日期、筛选区间和未完成项，后续据此填写文章的方法部分。

## 附件要怎样确认

JSON 中一条 `image` 或 `voice` 只能证明导出保留了这条消息。附件是否存在、是否能打开，要另外核对。

| 内容 | 建议抽查 |
|---|---|
| 图片 | 打开旧图，检查分辨率；原图、缩略图和缺失文件分开记 |
| 视频 | 播放开头和结尾，确认有声音，文件不是单张封面 |
| 表情 | 检查有实际图片或动图；只有资源标识并不代表图片已保存 |
| 语音 | 播放几条不同月份的文件，核对时长；原始音频与转写文字分别保留 |
| 文件与链接 | 附件是否还在；链接内容以后可能变化，可另存重要页面 |
| 通话 | 分别核对提示、通话类型、会话标识和时长，不把一次失败呼叫当作已接通通话 |

原始包里能保存多少，取决于微信中仍可读取的内容和导出工具。Nature Love 不恢复已过期附件，也不把图片、语音内容自动识别成文字。

## 转换脚本做了什么

在安装项目后执行：

```bash
python scripts/convert_wechatdataanalysis.py --input "private/original/conversations/目标联系人_标识/messages.json" --output private/messages.json
```

脚本面向 WeChatDataAnalysis 的 `schemaVersion: 1`，字段依据其[导出实现](https://github.com/LifeArchiveProject/WeChatDataAnalysis/blob/main/src/wechat_decrypt_tool/chat_export_service.py)核对。它独立实现字段转换，不读取微信数据库。

| 原字段 | 分析字段 / 处理 |
|---|---|
| `id`，缺失时使用有效的 `serverId` | `id`；没有稳定 ID 时不编造可跨导出去重的标识 |
| `createTime` | `timestamp` |
| `isSent` | `true → A`（导出账号），`false → B`（对方）；系统提示单列 |
| `renderType` | `type`；`emoji → sticker`、`voip → call`、`quote → text` |
| `content` | `text`；引用原文不再次拼入正文 |
| `voiceLength` | 毫秒除以 1000；缺失或零值保留为未知时长 |
| `emojiMd5` | `sticker_id` |
| `voipType` | `call_type` |

群聊、多个会话混在一起、发送方向不明或不符合结构的记录会停止转换。脚本不覆盖原文件或已有输出，也不丢弃无法识别的消息类型，而是将其归为 `other`。它只生成分析 JSON，原有附件、转写和附件相对路径仍在原始导出里，需要时按消息 ID 回查。

此格式的常规导出没有提供本项目去重所需的稳定通话会话 ID，通话时长也未必是独立字段。脚本保留通话提示及类型，不从“通话时长”“未接听”等正文猜出完整通话统计。若有另外核实的 `call_id` 与 `duration_seconds`，可加入标准输入；单次通话的双方提示使用相同会话 ID。

转换完成后，条数应与原 JSON 的 `messages` 数组一致。分析阶段的消息 ID 去重另记在 `summary.json` 的 `quality` 中。双方应抽查发送方向、日期和语音秒数，再据此写文章。

## 只保存片段：Mac 合并转发

[WeChatBridge](https://github.com/freestylefly/WeChatBridge) 可以接收 Mac 微信“转发到其他应用”生成的归档。其说明要求微信支持该分享功能；不同版本的入口和单批限制请查[使用指南](https://github.com/freestylefly/WeChatBridge/blob/main/USAGE.zh-CN.md)。

1. 安装并启用它的分享扩展。
2. 在微信中多选消息，选择合并转发，再进入“转发到其他应用”。
3. 选择微信流的“沉淀到文件夹”，或分批收集后保存。
4. 保留每一批的 ZIP、文字与附件，检查批次之间的日期有没有缺口或重复。

转发给微信联系人只会产生另一条微信消息。分享菜单里没有第三方入口时，先检查微信版本和扩展是否启用。

这条路线只覆盖手动选择的消息，不能自动遍历全部历史。TXT/Markdown 中缺少稳定消息 ID、精确时刻或通话元数据时，相应分析也会受限。本项目的 WeChatDataAnalysis 转换脚本不处理这种 ZIP；需要按[标准输入](INPUT_SCHEMA.md)另行整理。
