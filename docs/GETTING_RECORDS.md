# 从微信取得一份可分析的记录

保留两份东西：一份完整的原始导出，里面有消息和附件；一份供分析使用的标准 JSON。转换后的 JSON 不能代替原始归档。

## 本项目实际采用的路线

前期用微信流（WeChatBridge）接收过少量合并转发，取得的是片段。完整归档则在手机记录导入 Mac 后，先从本地微信取得并校验数据库密钥，再通过本地 WeChatDataAnalysis 服务导出 JSON 与媒体附件，最后另行整理通话会话和附件清单。

这几步各做一件事：微信负责迁移已有历史；数据库读取环节解决本机访问；导出服务保存消息与附件；Nature Love 负责清洗、统计、绘图和文章。微信流的分享扩展没有参与遍历完整历史。

本机曾使用临时微信副本完成密钥读取。这是针对当时环境的单独操作，没有打包进 Nature Love，也不是下面转换脚本的功能。其他人使用时，应先按导出工具当前支持的方式取得一份可读取的 JSON，再进入分析步骤。

## 手机记录与电脑记录

先在手机里找到这段聊天的最早日期。电脑登录时间较晚时，电脑上的记录可能只有其中一部分。

按 [README](../README.md#获取聊天记录) 中的手机导入步骤操作。完成后，在电脑微信里核对最早和最晚日期、几个中间月份，以及旧图片、视频和语音。针对电脑数据库的导出工具读取的是电脑中已有的历史。

“备份到电脑”保存的是恢复用的加密备份。它与导入电脑聊天是两个功能，也不会直接得到本项目接受的 JSON。入口和区别可参阅[华为的微信迁移说明](https://consumer.huawei.com/cn/support/content/zh-cn01118496/)；其他系统仍需核对自己的客户端。

## 导出一位联系人的完整记录

完整归档使用 [WeChatDataAnalysis](https://github.com/LifeArchiveProject/WeChatDataAnalysis) 的本地导出服务。先在它的说明和 Releases 中核对系统、芯片和微信版本，再按该工具的步骤连接自己的数据。先取得并校验密钥，确认能浏览目标会话，再创建导出任务；Nature Love 不负责获取密钥。

能浏览聊天后，按下列设置导出：

| 选项 | 选择 |
|---|---|
| 会话 | 要分析的那一位联系人，单聊 |
| 时间 | 全部，或你明确想研究的完整区间 |
| 消息类型 | 全部，保留系统提示、媒体和通话提示 |
| 格式 | JSON；可另存 HTML 方便人工对照 |
| 媒体 | 需要归档的图片、视频、表情、语音、文件均勾选 |

保留下载的压缩包，再解压到 `private/original/`。在解压目录中找到目标联系人的 `messages.json`，不要误选整个任务的 `manifest.json`、`report.json` 或 `meta.json`。

记录导出工具版本、微信版本、导出日期和筛选区间。这些信息以后写方法部分会用到。导出失败的项目也保留在原始报告里。

若导出时对正文做了脱敏，词语和话题分析也只对应脱敏后的文字。

## 附件要怎样确认

JSON 中一条 `image` 或 `voice` 只能证明导出保留了这条消息。附件是否存在、是否能打开，要另外核对。

| 内容 | 建议抽查 |
|---|---|
| 图片 | 打开旧图，检查分辨率；原图、缩略图和缺失文件分开记 |
| 视频 | 播放开头和结尾，确认有声音，文件不是单张封面 |
| 表情 | 检查有实际图片或动图；只有资源标识并不代表图片已保存 |
| 语音 | 播放几条不同月份的文件，核对时长；原始音频与转写文字分别保留 |
| 文件与链接 | 附件是否还在；链接内容以后可能变化，可另存重要页面 |
| 通话 | 分别核对提示、通话类型、会话标识和时长，不把一次失败呼叫当作已接通通话 |

原始包里能保存多少，取决于微信中仍可读取的内容和导出工具。Nature Love 不恢复已过期附件，也不把图片、语音内容自动识别成文字。

## 转换脚本做了什么

在安装项目后执行：

```bash
python scripts/convert_wechatdataanalysis.py --input "private/original/目标联系人/messages.json" --output private/messages.json
```

脚本面向 WeChatDataAnalysis 的 `schemaVersion: 1`，字段依据其[导出实现](https://github.com/LifeArchiveProject/WeChatDataAnalysis/blob/main/src/wechat_decrypt_tool/chat_export_service.py)核对。它独立实现字段转换，不读取微信数据库。

| 原字段 | 分析字段 / 处理 |
|---|---|
| `id`，缺失时使用有效的 `serverId` | `id`；没有稳定 ID 时不编造可跨导出去重的标识 |
| `createTime` | `timestamp` |
| `isSent` | `true → A`（导出账号），`false → B`（对方）；系统提示单列 |
| `renderType` | `type`；`emoji → sticker`、`voip → call`、`quote → text` |
| `content` | `text`；引用原文不再次拼入正文 |
| `voiceLength` | 毫秒除以 1000；缺失或零值保留为未知时长 |
| `emojiMd5` | `sticker_id` |
| `voipType` | `call_type` |

群聊、多个会话混在一起、发送方向不明或不符合结构的记录会停止转换。脚本不覆盖原文件或已有输出，也不丢弃无法识别的消息类型，而是将其归为 `other`。它只生成分析 JSON，原有附件、转写和附件相对路径仍在原始导出里，需要时按消息 ID 回查。

此格式的常规导出没有提供本项目去重所需的稳定通话会话 ID，通话时长也未必是独立字段。脚本保留通话提示及类型，不从“通话时长”“未接听”等正文猜出完整通话统计。若有另外核实的 `call_id` 与 `duration_seconds`，可加入标准输入；单次通话的双方提示使用相同会话 ID。

转换完成后，条数应与原 JSON 的 `messages` 数组一致。分析阶段的消息 ID 去重另记在 `summary.json` 的 `quality` 中。双方应抽查发送方向、日期和语音秒数，再据此写文章。

## 只保存片段：Mac 合并转发

[WeChatBridge](https://github.com/freestylefly/WeChatBridge) 可以接收 Mac 微信“转发到其他应用”生成的归档。其说明要求微信支持该分享功能；不同版本的入口和单批限制请查[使用指南](https://github.com/freestylefly/WeChatBridge/blob/main/USAGE.zh-CN.md)。

1. 安装并启用它的分享扩展。
2. 在微信中多选消息，选择合并转发，再进入“转发到其他应用”。
3. 选择微信流的“沉淀到文件夹”，或分批收集后保存。
4. 保留每一批的 ZIP、文字与附件，检查批次之间的日期有没有缺口或重复。

转发给微信联系人只会产生另一条微信消息。分享菜单里没有第三方入口时，先检查微信版本和扩展是否启用。

这条路线只覆盖手动选择的消息，不能自动遍历全部历史。TXT/Markdown 中缺少稳定消息 ID、精确时刻或通话元数据时，相应分析也会受限。本项目的 WeChatDataAnalysis 转换脚本不处理这种 ZIP；需要按[标准输入](INPUT_SCHEMA.md)另行整理。
